Human review procedure:
1. Read each actual crop, independently of AI/OCR guesses and route references.
2. Enter visible text, legibility and field status. Preserve case, punctuation,
   leading zeros and real line breaks. Do not complete a route from memory.
3. Use [UNK] for unresolved spans; partial text includes [UNK], wholly illegible
   text is [UNK]. Blank/absent fields have empty text and not_applicable state.
4. Enter the actual human name and actual review date. No AI may attest for them.
5. Drafts save locally when browser storage permits; export CSV to submit.
   Storage failure is shown explicitly. Export before closing if saving fails.
   Exports now include the review set, reviewer and date in the filename.
   Incomplete touched rows block export and list their IDs; no silent omission.
6. Record row IDs, corrections, unresolved items and the saved return path in
   the log at the end of this file. Blank or untouched rows remain pending.

MATCHING CONTRACT AND USER-OWNED WORK

Final matching_inputs.jsonl: one crop/model record, no ground-truth labels.
Required: record_id; split valid/test; input_set annotation/prediction;
field bus_number/destination/route_text/front_eds; source_image; crop;
box_xyxy; candidate_display_id; exact raw_ocr_text; normalised_ocr_text;
prediction_status success/error/missing; OCR and detector confidence separately.
Every crop needs a display ID identifying its actual display. A filename or
photo alone is not proof that two crops belong to the same display.
Keep validation/test labels in separate CSVs with review_id and a documented
record_id join. No final selected-model JSONL has been produced.

The user will implement reference matching, not Codex in this task:
- Keep successful inputs, group by display, normalise for matching while
  preserving raw OCR. Service numbers match exactly: 97E differs from 97;
  leading zeros remain. Destinations use fuzzy matching and a margin rule.
- Number only: accept valid exact service; infer destination only if reference
  and direction identify one. Destination only: require cutoff and clear lead;
  infer number only for a unique service.
- Number plus destination: number narrows search; below cutoff unresolved;
  strong evidence for a different service flags conflict.
- Route-only: preserve OCR, service unresolved; CSV has no road-name coverage.
- Whole-display text may supply number plus destination. Crop/panel agreement
  keeps one value and logs both; disagreement requires other-field/reference
  evidence or remains unresolved. Resolve ties with same-display evidence;
  retain a value shared by tied candidates. Record reasons for no usable fields.
- The app displays only accepted matches, withholding guesses/conflicts/ties.
- Tune cutoffs 25/50/75 and margin on VAL only, freeze, then run matching TEST
  once. Per field and crop population, compare raw/matched exactness, accepted
  rate and accepted accuracy, rescued and harmful corrections, valid-but-wrong
  numbers (97 for 97E), and unresolved count.
